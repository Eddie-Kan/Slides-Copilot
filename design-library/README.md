# 把你喜欢的设计放进来

这个目录用来收集你觉得设计好的 PPT 页面，以及对它们的简短分析。参考不一定要整套保存；一张封面、一张内容页，或者一张图表，都可以说明你喜欢什么。

**为避免版权问题，公开版本不附带原包里的两张风格参考图，对应解读也已删除。请自己补充有权使用的参考。**

## 怎么添加

把 PPT 页面导出为 PNG、JPG 或清晰截图，放到 `images/`，也可以用子目录分类。Agent 会在设计时主动查看，按当前任务选用，不需要你逐张介绍，也不需要先写 Markdown 或重建索引。已有作品仍以已确认的设计方向为准。

## 可选：保留参考解读

需要把有用的观察整理成可检索资料时，由 Agent 按参考分析技能保存简短解读并更新索引；你也可以自行补充。图片来源和授权情况应按已知信息记录，不凭空推断。仅供当前作品使用的偏好保留在作品记录中。

例如，`images/my-reference.png` 的配套解读可以保存为 `my-reference.md`：

```markdown
# 参考名称

关键词：蓝白、医疗、内容饱满、清晰分组。

![参考页面的简短描述](images/my-reference.png)

## 图片来源

- 作者或出处：
- 可以怎样使用，是否允许公开分享：

## 喜欢它的哪些地方

- 配色和明暗：
- 内容多少、分组和间距：
- 标题与主视觉：
- 哪些地方适合这次项目：
- 哪些品牌、文案、数据不能照搬：
```

上面的名称和路径只是示例，请替换成实际文件。没有参考时，也可以让助手先提出设计方向，再用样稿讨论。

## 准备分享时，留意这两点

**第一，本地参考不等于可以公开传播。** 新增图片和解读默认被 `.gitignore` 忽略，不会被 `git add .` 加入暂存区。确认可以公开分发后，再单独添加经过检查的文件；必要时用 `git add -f`，不要强制添加整个目录。

**第二，检索索引会保存解读正文。** 即使原文件被 Git 忽略，重新生成的 `rag/index.json` 也可能收录它的内容。准备发布时，先把不公开的参考和解读移到仓库之外，再重建索引并检查差异。

如果参考只用于某套作品，可以直接放在那套作品的本地目录里，由助手打开查看，不必加入通用设计库。

更多分析方法见 [参考与填充度](../handbook/reference.md)。
