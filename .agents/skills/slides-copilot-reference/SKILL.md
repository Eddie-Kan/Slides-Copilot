# 参考分析

读取 [参考与填充度](../../../handbook/reference.md)，实际打开用户提供的图。拼图先辨认各实际页面，再看整体；小字或局部不清楚时打开原尺寸查看，不臆测。

用户放入项目根目录 `design-library/images/` 的图片也是参考来源，不要求用户逐张指定或先写解读。主动检查目录及子目录，查看图片；数量较多时先用缩略总览浏览，再打开与当前任务相关的原图。已有解读可辅助理解，但文件名、文字标签和检索结果不能代替看图，也不能因图片未被索引而跳过。库中收藏不等于当前项目指定的风格，结合任务与已确认要求判断哪些特点适用。

向用户反馈最有用的三件事：配色关系、页面填充程度、对本项目的应用建议。只有偏好仍有歧义时，再拿具体差异询问。用户给图并不意味着要求照搬构图。

为当前项目保留一段简洁的参考解读：

- 主要颜色、明暗、饱和度、强调色及面积关系。
- 文字与主视觉占比、信息量、板块间距、整体饱满程度。
- 标题气质、材质、光影和形状语言。
- 当前项目适合继承的特点，以及具体内容引起的变化。

参考整套时，看封面和内页如何共同构成视觉系统。用户只给封面而项目有大量正文时，主动提出一张内容页样稿验证承载能力。

需要扩展设计库时，保存图片和独立的 Markdown 解读，说明适用场景、观察位置、可迁移方法。视觉难点使用 [解释性说明](../../../visuals/README.md) 的形式记录。只保存有明确用途的内容，不批量堆积重复图片。

新增或更新资料后，在项目根目录运行 `python3 tools/retrieve.py --rebuild`。当前项目的私有偏好保留在项目记录中，不自动升级为所有项目的通用规则。
